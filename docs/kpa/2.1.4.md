# 奇谱发生器 2.1.4 发布日志

<Head version="2.1.4"/>

这是一次小更新。

## 【上游】奇谱

### 新功能特性
现在错误对象可以带参数，这使得在编辑器中能够方便地追踪到错误所在位置。

例如：
```ts
err.EVENT_NODE_NOT_DENSE().warn(node);
```

这将挂载 `node` 到错误对象中。当从缓冲区获得这个错误时，就能用 `args` 属性获取到它。

```ts

const errors = KPAError.buffer;

for (const err of errors) {
    if (err.id === ERROR_IDS.EVENT_NODE_NOT_DENSE) {
        const node = (err as KPAError<ERROR_IDS.EVENT_NODE_NOT_DENSE>).args[0];
        console.log(node);
    }
}
```

此过程是类型安全的，不过缺点是需要繁琐的断言（TypeScript语言服务不能从属性判断中反推泛型）。

<Kp hash="deafac9"/>

### 错误修复与优化

#### RPEVersion
先前 KPA 谱面编译器输出的 `RPEVersion` 一直为 `1`。当谱面被导入到 RPE 时，由于这个字段过低，一些属性会被直接忽略（如 Note 的不透明度值）。现在，编译器将输出 `"RPEVersion": 170`。

<Kp hash="3a95f34"/>

#### 排序事件
先前，Kipphi 默认事件列表是有序的，但在 Aax1dφ 的反馈中发现 [Phichain](https://github.com/Ivam-1F/Phichain) 导出的谱面中事件是无序排列的，与 Re:PhiEdit 不同。为了适配，在 2.1.4 中，Kipphi 默认事件列表是无序的，会先进行排序。

然而 Phichain 导出的谱面当中还发现事件是允许重叠的。我们希望 Phichain 方面能够解决这个问题。

<Kp hash="b41728a"/>

#### 空线剥离 
在 2.1.3 中我们加入了空线剥离功能，但发现由于删除判定线后后方判定线前移，导致其他判定线对该线的引用发生了错位。此版本修复了该问题。

<Kp hash="3a95f34"/>

#### 杂项
1. 为了适配 Re:PhiEdit，谱面编译时纹理名称转换为纯ASCII，非ASCII字符会被转换为 `u(hhhh)` 的形式，可通过 `RPEChartCompiler.replaceFilename()` 静态方法生成转换后的纹理名。<Kp hash="3a95f34"/>

## 【上游】奇谱播放器

### 新功能特性
现在左上角会实时显示渲染的故事版贴图个数。<Kpp hash="c97854d" />

### 错误修复与优化
1. 修复错误的不透明度应用逻辑，现在绑定UI和文本能够正确应用透明度。<Kpp hash="390fe72"/>
1. alpha 小于等于 0 时跳过贴图/文字渲染，提升效率。<Kpp hash="2e86bff" />
1. 对Phira资源包添加了方言属性 `useAudio`，指定使用的打击音效的类型，这使得打击特效不必须为 `ogg`。（然而这个属性很快就要用不到了）<Kpp hash="d89a5fc" />
1. 修复了音符渲染逻辑，现在双押的渲染会参考对应音符单押的贴图大小。<Kpp hash="084d551" />

## 【上游】奇谱画布编辑器

新功能特性：现在两个编辑器会显示选中元素数量和剪切板元素数量。<Kpce hash="27a1e78" />

## 【本体】奇谱发生器

### 新功能特性

#### 重放补偿和全局基础偏移
- 重放补偿：指定暂停后点击继续播放时向前跳跃的时间。
- 全局基础偏移：该偏移量会附加到所有谱面，仅对奇谱发生器本身作调节。您应当在写谱之前先用已校准的谱面调节这个项目。

这两个项目在“通用设置”中编辑。
<Kpa hash="2f1d1f5" />

#### 错误页增强
现在可以在“谱面错误”次侧栏中直接跳转到错误目标。仅支持小部分错误。<Kpa hash=d3e4f42 />

### 错误修复与优化
1. 修复导入谱面时缺乏元数据卡死，并增多导入时反馈。<Kpa hash="f62899d" />
1. 调整资源包选择页的布局。<Kpa hash="e460364" />
1. 调整默认全局基础偏移为 36ms。<Kpa hash="a896e92" />
1. 音画偏移现在会持久化到 `localStorage` 中。<Kpa hash="b00be9d" />
1. 现在当播放器长宽比大于左上区时播放器不超出，而是在下方留出空白。<Kpa hash=55b9925 />
1. 导出时 `info.txt` 添加随机的 `Path` 使得 RPE 能够导入；同时导出时确保所有贴图为纯 ASCII；重载Mime使得 `audio/mpeg` 返回 `.mp3`。<Kpa hash="2f532bb" />
